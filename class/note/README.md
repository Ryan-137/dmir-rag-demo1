# 第 15 周课程展示任务整理

展示时间：2026-06-09，第 15 周最后一节课。

## 展示目标

围绕两个任务构建 RAG 验证案例，分别展示系统在研究论文理解和 QA 搜索引擎数据问答上的检索增强效果。两个任务都需要体现：原始大模型在没有外部检索时回答不稳定或不充分，接入检索、分块、向量索引和生成优化后，能够给出更准确、更完整、更有依据的回答。

## 两个展示任务

### 任务一：新研究论文验证

- 选择一篇新的、基础大模型大概率未充分掌握的研究论文作为验证材料。
- 设计一组能体现论文细节理解的问题，例如方法细节、实验设置、关键结论、消融实验和局限性。
- 记录未使用检索时的大模型回答，作为 baseline。
- 记录使用系统检索增强后的回答，并对比准确性、引用依据和完整性。
- 展示检索前后模型能力的明显差异。

### 任务二：QA 搜索引擎数据验证

- 使用之前 QA 搜索引擎任务中的数据作为第二个验证材料。
- 保留原 QA 搜索场景的问题、候选答案或文档集合，作为检索增强问答的业务数据。
- 设计一组能体现搜索质量和回答质量的问题，例如事实定位、答案摘要、多文档归纳和相似问题区分。
- 记录未使用检索时的大模型回答，作为 QA 任务 baseline。
- 记录使用 QA 数据检索增强后的回答，并对比命中证据、答案准确性和可解释性。
- 展示系统不仅适用于论文 RAG，也适用于已有 QA 搜索引擎数据。

## 模型选择

两个任务都需要分别选择并实现两类模型：

- 嵌入模型：选择适合研究论文和 QA 搜索数据的语义表示模型。
- 大语言模型：选择适合论文问答、QA 回答、总结和解释的大模型。

每类模型都需要支持两种调用方案：

- API 调用：通过远程服务完成推理。
- 本地推理：在本地模型路径或本地服务中完成推理。

## 前端功能任务

- 基于 React 框架增加一项可展示的新功能。
- 可优先考虑将生成结果从纯文本输出增强为 Markdown 渲染。
- Markdown 输出需要支持标题、列表、表格、代码块和引用等常见问答格式。
- 前端最好能区分论文任务和 QA 搜索任务，便于课堂展示时快速切换数据与问题。

## 文件解析任务

论文任务中的 PDF 解析需要覆盖不同文件形态：

- 普通文本层 PDF。
- 多层次渲染或复杂版式 PDF。
- OCR 型 PDF。
- 先转换为 Markdown，再进入解析流程的方案。

QA 搜索引擎数据需要梳理原始数据格式，并明确如何转换为系统可处理的文档或问答片段。

目标是比较不同解析和数据转换方案对后续分块、嵌入和检索质量的影响。

## 向量库任务

- 支持多种向量索引方式。
- 对比不同索引方式在检索速度、召回质量和配置复杂度上的差异。
- 分别展示论文数据和 QA 搜索数据在不同索引策略下的检索表现。

## 检索与生成优化

响应生成阶段需要增加检索前和检索后的优化：

- 检索前优化：查询改写、关键词扩展、问题拆解、论文术语归一化、QA 问题标准化。
- 检索后优化：结果重排、上下文压缩、去重、证据片段筛选。
- 生成优化：要求模型基于检索上下文回答，并尽量标注依据来源。

展示时需要突出优化前后回答质量的变化。

## 分块策略实验

针对研究论文特点设计专门的分块算法，可以重点考虑：

- 按章节结构分块，例如 Abstract、Introduction、Method、Experiments、Conclusion。
- 按标题层级和段落边界分块。
- 保留公式、表格、图注和引用上下文。
- 针对论文问答任务控制 chunk 大小和 overlap。
- 参考 BERT 相关任务思路，探索是否需要微调嵌入模型。

针对 QA 搜索引擎数据，可以重点考虑：

- 按问题、答案、上下文或知识条目组织 chunk。
- 保留原始问题和标准答案之间的关联。
- 将相似问题、别名和关键词写入 metadata，便于检索和重排。
- 对长答案或多段解释做适度切分，避免单个 chunk 过长。

当前目录中的 `exp` 脚本可以作为分块策略实验入口：

- `TextSplitter.py`：基础文本分块实验。
- `RecursiveTextSplitter.py`：递归式文本分块实验。
- `StructureTextSplitter.py`：结构化文本分块实验。
- `CodeSplitter.py`：代码或结构化符号内容分块实验。
- `SemmanticTextSplitter.py`：语义分块实验。

## 建议展示流程

1. 介绍两个展示任务：新研究论文验证和 QA 搜索引擎数据验证。
2. 分别展示两个任务在未使用检索时的大模型回答。
3. 展示论文 PDF 解析、QA 数据转换、分块、嵌入和索引流程。
4. 展示两个任务的检索结果和命中证据片段。
5. 展示两个任务接入检索增强后的回答。
6. 对比优化前后效果，说明改进来自哪些模块。
7. 总结系统当前能力、限制和后续改进方向。
